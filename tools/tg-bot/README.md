# Telegram, критерий 21

Бот шлёт начальнику смены предупреждение заранее, как только `GET /api/alerts` отдаёт риск (окно `alert_before_secs`, на карте 5 минут). Текст: «не успевает, ближайший свободный – инженер …, успевает с запасом … мин». Кнопка вызывает `POST /api/requests/{id}/reassign`.

Бэкенд и фронт не меняются. Сервис встаёт рядом с уже запущенным API.

## Локально

Скопируй `.env.example` в `.env`. `API_BASE` для машины без Docker: `http://127.0.0.1:3001`. Почта и пароль — диспетчер.

```text
python -m oto_bot
```

В Telegram: `/start`. Дальше риски приходят сами. `/risks` показывает текущие, `/stop` отключает чат.

## На том же сервере

Рядом с бэкендом на порту 3001:

```text
docker compose up -d --build
```

`API_BASE=http://host.docker.internal:3001` уже в примере. Если API в другой docker-сети, поставь его адрес. `TELEGRAM_CHAT_ID` можно не задавать: первый `/start` привяжет чат, файл лежит в томе `tg_bot_data`.
