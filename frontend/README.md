# Прототип карты (Tiled → Leaflet)

Быстрый прототип для веб-части хакатона: показывает карту `et.tmj` (сделана в
[Tiled](https://www.mapeditor.org/)) на Leaflet, без бэкенда — чистый
HTML/JS/CSS, ничего собирать не нужно.

## Запуск

Браузер не даёт делать `fetch()` файлов с диска напрямую (`file://`), поэтому
нужен любой статический сервер, поднятый **из корня репозитория**:

```bash
# из корня digital_challenge/
python -m http.server 8000
# или
npx serve .
```

Дальше открой `http://localhost:8000/frontend/index.html`.

Скрипт сам найдёт `et.tmj` (пробует `../et.tmj`, `./et.tmj`, `/et.tmj`).

## Как это устроено

### 1. Tiled ≠ гео-карта → `L.CRS.Simple`

Обычный Leaflet заточен под карты Земли (широта/долгота, тайлы OSM). Наша
карта — это просто сетка пикселей игрового уровня. Поэтому используется
`L.CRS.Simple`: координаты — это пиксели картинки, ось Y инвертирована
относительно Tiled (в Leaflet "выше" = больше `lat`, в Tiled "ниже" = больше
`row`). В `map.js` это учтено при переводе клика мышкой обратно в
`row/col` (см. `main()`).

### 2. Формат `.tmj`

Это JSON-экспорт Tiled (то же самое, что `.tmc`/старый `.tmx`, только в JSON).
Важные поля:

- `width`, `height` — размер карты в тайлах (у нас 64×64).
- `tilewidth`, `tileheight` — размер одного тайла в пикселях (16×16).
- `layers[]` — слои. У каждого `tilelayer` есть `data` — плоский массив чисел
  длиной `width*height`. Индекс в массиве = `row * width + col`.
- `tilesets[]` — ссылки на файлы тайлсетов (`.tsx`) с описанием спрайтов и
  `firstgid` — с какого числа начинается нумерация тайлов этого тайлсета.

Число в `data[i]` — это **gid** (global id) тайла. `0` — клетка пустая.

### 3. Флаги отражения тайла

Tiled хранит "тайл отражён по горизонтали/вертикали/диагонали" в старших
битах того же числа (см. [спецификацию](https://doc.mapeditor.org/en/stable/reference/global-tile-ids/)):

```
0x80000000 — flipped horizontally
0x40000000 — flipped vertically
0x20000000 — flipped diagonally
```

Если это не отфильтровать, реальный id тайла будет "случайным" огромным
числом (в `et.tmj` такие значения — `2684355023` и т.п.). Функция
`decodeGid()` в `map.js` их снимает и возвращает чистый `gid` + три флага.

### 4. Рендер без спрайтов (пока)

`.tmj` ссылается на два тайлсета (`tilemap_packed.tsx`, `enemy_1_b_m.tsx`), но
самих картинок (`.png`) в репозитории нет — только карта. Поэтому сейчас
тайлы рисуются цветными плейсхолдерами по слоям (см. `LAYER_COLORS` в
`map.js`), с небольшой цветовой вариацией по `gid`, чтобы отличать разные
тайлы визуально.

**Как подключить настоящий тайлсет**, когда появится PNG:

1. Попроси у того, кто делал карту, `tilemap_packed.png` (и второй, если
   нужны враги/техника) + сами `.tsx` файлы (в них есть `columns`,
   `tilewidth`, `spacing`, `margin`).
2. Положи PNG в `frontend/assets/`.
3. В `map.js` в `CONFIG.tilesetImage` выстави `enabled: true` и впиши точные
   значения из `.tsx`.
4. Замени `renderCanvas()` так, чтобы вместо `ctx.fillRect(...)` тайлы
   вырезались из спрайт-листа: зная `gid - firstgid`, вычисляешь
   `col = idx % columns`, `row = Math.floor(idx / columns)`, и рисуешь
   `ctx.drawImage(atlasImg, col*tileW, row*tileH, tileW, tileH, dstX, dstY, tileW, tileH)`.
   Для флагов отражения — `ctx.save()/scale(-1,1)/...` перед `drawImage`.

Сам pipeline (загрузка `.tmj`, декодирование gid, сетка `grid[row][col]`,
клик → координаты тайла) менять не придётся — это уже сделано.

## Как подключать *свои* карты

1. В Tiled: `File → Export As... → JSON map files (*.tmj)`.
2. Держи тайлсет **встроенным** (embed tileset) *или* клади рядом `.tsx` +
   `.png` — если внешний, `map.js` для реального рендера должен уметь читать
   путь тайлсета оттуда же, где лежит `.tmj`.
3. Обнови `CONFIG.mapCandidates` в `map.js`, если файл называется иначе, чем
   `et.tmj`, либо просто переименуй новый экспорт в `et.tmj`.
4. Если в карте другие названия слоёв (не `основа/дорога/здание/...`) —
   допиши цвета в `LAYER_COLORS`, иначе слой просто получит цвет по
   умолчанию (`DEFAULT_COLOR`).

## Стык с бэкендом (следующий шаг)

Бэкенд (`backend/src/parser.rs`) парсит тот же `.tmj` в матрицу и гоняет BFS
по "дорогам" (`backend/src/main.rs`: `HashSet::from([29, 0])` — id тайлов
основы/пустой клетки, которые считаются проходимыми). План интеграции:

1. Поднять бэкенд как HTTP-сервис (сейчас это просто `main()`, печатающий
   маршрут в консоль) с эндпоинтом вида `POST /route { from, to }`.
2. На фронте по клику "старт"/"финиш" отправлять `row/col` на бэкенд.
3. Полученный список точек рисовать как `L.polyline` поверх той же сетки
   (координаты те же: `x = col*tileW + tileW/2`, `y` — с учётом инверсии оси,
   как в обработчике клика в `map.js`).

Сама система координат (`L.CRS.Simple`, привязка `row/col` к пикселям) уже
совместима 1:в:1 с тем, что использует бэкенд — конвертация не потребуется,
кроме инверсии оси Y, которая уже реализована.
