=== How to read the applied:false acknowledgement among the 200s ===
Case 5 — the unknown-object rule: zzz-unknown-999 is in neither the active map nor the
  engineer table, so the point is acknowledged (accepted true, 200) and not applied.
Case 7a-replay — the stale-sample rule, not a regression: the literal %TIMESTAMP value 1764000000
  is 2025-11-24T16:00:00Z, older than the point already stored for e-01, so the repeated
  line is acknowledged and ignored — exactly what a GPSLogger queue replay must get. Case
  7a sends the same query shape with the device's own clock and returns applied:true.
While probing, a point jumping tens of metres within milliseconds was also acknowledged with
applied:false by the outlier guard; that guard is why case 1 and case 6 reuse one coordinate.
